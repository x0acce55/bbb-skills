# ADR-0017: Reachability is generated and verified

Amends [[ADR-0012-bidirectional-routing]].

## Context

ADR-0012 claimed that traversal by clicking and traversal by an agent following forward
links reach the same set of files. The claim was never tested.

The first reachability check found it false. Daily notes were unreachable from the home
note, which described `daily/` in prose rather than linking to it. Projects were
reachable only by accident -- through the decisions ledger, via ADRs that happened to
reference them. A project with no ADR would have been orphaned, and nothing would have
said so.

An invariant nobody checks is a belief, not an invariant.

## Decision

The home note's project list and the daily index are generated by `build_index.py`, the
same way project indexes are. `daily/daily.md` is a generated index of every daily note.

`health_report.py` walks the link graph from the home note and reports anything it
cannot reach. The claim in ADR-0012 is now tested on every run.

## Rejected

**Linking daily notes from the home note directly.** They accumulate forever; the home
note would become a list of dates.

**Exempting `daily/` from the reachability claim.** Would make the claim true by
narrowing it, and daily notes are exactly the ones later searched for by date rather than
remembered by name.

**Leaving projects reachable through the decisions ledger.** It worked, by coincidence,
and would have broken silently for the first project that made no decisions.

## Consequences

`daily/daily.md` grows by one row a day. It is a browsing index and is not loaded at
session start, so the cost is disk rather than context.

The reachability check is the slowest thing in the health report, since it walks the
whole graph. That is acceptable for something run monthly rather than per-session.
